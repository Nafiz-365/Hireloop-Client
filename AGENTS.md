## Commands

```bash
npm run dev        # Next dev server on port 3000 (BETTER_AUTH_URL assumes it)
npm run format     # prettier --write on **/*.{ts,tsx} only (not CSS/MD)
npm run typecheck  # tsc --noEmit
npm run lint       # eslint (flat config, eslint-config-next)
npm run build      # next build --webpack (the script forces webpack; don't run bare `next build`)
```

- No test suite exists — don't look for one.
- Verify in this order: `format` → `typecheck` → `lint` → `build`. Prettier reorders Tailwind classes, so format before linting/diffing. There is no CI — this local chain is the only gate; last verified passing Nov 2026.
- Moving/deleting routes under `app/` can leave stale `.next/types` that fail `npm run typecheck` with `Cannot find module '...app/page.js'` — delete `.next/types` and rerun (the next build regenerates it).
- A dev server may already be running on port 3000; `npm start` then fails with EADDRINUSE.
- `.env*` is gitignored — a fresh clone has none. Next loads `.env` automatically; it must contain at least `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL=http://localhost:3000`, and `MONGODB_URI` (auth fails at startup without it).
- `npm run build` prints `WARN [Better Auth]: Social provider google is missing clientId or clientSecret` — expected (Google env vars are unset), not a regression.

## Toolchain quirks

- **shadcn is Base UI here** (`@base-ui/react`), not Radix. To render a Button as a link: `render={<Link href="..." />}` plus `nativeButton={false}` — omitting `nativeButton={false}` produces a nested `<a><a>` (see `features/home/components/Cta.tsx`, `features/auth/components/AuthForm.tsx`). Add new primitives with `npx shadcn@latest add <component>`.
- `npx shadcn@latest add` can **overwrite** existing `components/ui/*` files (pass `--overwrite` to skip the prompt). Two known traps: the registry's `input.tsx` rewrite **drops `suppressHydrationWarning`** (re-apply it — see the input bullet below; diff against a backup), and the registry's `hooks/use-mobile.ts` fails `react-hooks/set-state-in-effect` — the committed version uses `useSyncExternalStore` instead, don't re-add the registry one.
- `cn` is the `cn` npm package (no local helper) and **merges conflicting Tailwind classes like tailwind-merge, so an override wins when passed last**. Both `components/ui/*` and feature modules import through the re-export at `@/lib/utils`. Prettier's `tailwindFunctions` is `["cn", "cva"]`.
- **Tailwind v4**: no `tailwind.config.*`; theme lives in `app/globals.css` under `@theme inline`. `--radius: 0.625rem` and its `--radius-*` scales do not match Figma pixel radii — use arbitrary values (`rounded-[24px]`) when matching the design.
- Fonts: design fonts are exported from `lib/fonts.ts` via `next/font` and applied by passing `className` to elements — their `--font-*` variables are **not** consumed anywhere in CSS. The exception is `app/layout.tsx`, which loads Geist/Geist_Mono with `variable` and feeds the `font-sans`/`font-mono` theme tokens in `@theme inline`. `Space_Mono` requires an explicit `weight: ["400","700"]` (it has no variable axis).
- ESLint flat config (`eslint.config.mjs`) ignores `.next/`, `out/`, `build/`, `next-env.d.ts`.
- `zod` is a **direct** dependency (v4) — used server-side in `lib/auth.ts` for the `role` field's `validator.input` (Standard Schema). Mind the v4 API: `z.email()`, `z.enum([...])` (not `z.string().email()`).

## Architecture

- App Router, single package (no workspaces). Path alias `@/*` → repo root (tsconfig). Two route groups split the shells: `app/(public)/*` (Navbar: homepage + `(auth)` login/signup) and `app/(dashboard)/*` (sidebar shell) — group names never appear in URLs.
- `app/(public)/page.tsx` = homepage; its sections live in `features/home/components/*` (Hero, Stats, Features, Cta), `features/jobs/components/JobsPreview.tsx`, and `features/pricing/components/PricingSection.tsx`. The global shell lives in `components/layout/*` — `Navbar.tsx` renders in `app/(public)/layout.tsx` (sticky wrapper) while `Footer.tsx` is rendered only by the homepage (auth pages and dashboards have no footer). Shared common elements live in `components/common/*` (`Icon.tsx`, `SectionLabel.tsx`), and the shared primitives in `components/ui/*` (avatar, badge, button, card, dropdown-menu, input, separator, sheet, sidebar, skeleton, table, tooltip) plus `hooks/use-mobile.ts`. `"use client"` only where a component uses Button/Input/useState/hooks; the rest are server components.
- Navbar (`components/layout/Navbar.tsx`) renders once in `app/(public)/layout.tsx` (sticky wrapper) — every public page gets it, dashboard routes use the sidebar shell instead; never render `<Navbar />` inside a page. It reads the session via `authClient.useSession()`: logged-out → Sign In / Get Started; logged-in → two things. (1) The nav list appends a **Dashboard** entry: the module-level `navLinks` array (Browse Jobs / Company / Pricing) is extended in-component as `links` only when `session.user` exists — href from the shared `dashboardHref(user)` helper (`roleHome[normalizeRole(role)]`, pre-role accounts fall back to seeker), rendered in both the desktop `<ul>` and the mobile Sheet, active state via `pathname.startsWith`. (2) An avatar-only trigger (shadcn Base UI `DropdownMenu`, shared `UserMenu` component — same on desktop and mobile) opening a menu with name / email / role badge + the same role-aware Dashboard link (Base UI `render={<Link/>}`) + Sign Out (`authClient.signOut()`, no reload — the client cache clears itself); the trigger avatar is default size (32px), photo when `session.user.image` exists else a first-letter fallback. The mobile Sheet is navigation-only when logged-in (auth buttons render only logged-out); `isPending` renders a blank action slot to avoid a Sign In flash.
- Homepage content is **static mock data** — jobs from `features/jobs/data/mock-jobs.ts`, pricing from `features/pricing/data/plans.ts` (imported relatively, e.g. `../data/plans`); no content API exists yet.
- Navbar `navLinks` and several homepage CTAs point to `/jobs`, `/companies`, `/pricing` — **no routes exist for them yet** (only `/`, `/login`, `/signup`, `/dashboard/*`), so they 404 with Next's default page. Expected while the `Public / Browse Jobs` etc. frames are pending; don't "fix" it by inventing placeholder pages.
- Dark-only app: no theme provider. `next-themes` was removed because `enableSystem` caused an unfixable SSR hydration mismatch on `<html>` (`style={{color-scheme}}`) — don't re-add theme switching, and don't put `suppressHydrationWarning` on `<html>`.
- `components/ui/input.tsx` sets `suppressHydrationWarning` on the `<input>` **on purpose**: browser extensions (temp-mail/autofill) inject attributes such as `data-temp-mail-org` into inputs before React hydrates, and React 19 reports extra DOM attributes as a fatal hydration mismatch (see `warnForExtraAttributes` in `react-dom-client.development.js`). It skips attribute comparison for that element only — don't spread it to other elements.
- Auth: better-auth with MongoDB adapter. Server config is `lib/auth.ts` — reads `MONGODB_URI` from `.env` (Atlas cluster, loaded at module start) and uses database `hireloop_db`; enables email/password plus a Google social provider reading `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (still unset in `.env` → the build's Google warning is expected). Route handler: `app/api/auth/[...all]/route.ts`. Signup carries a `role` via `user.additionalFields.role` (zod-enum `seeker|recruiter|admin`, default `seeker`) — note **admin is self-selectable** until restricted.
- Static assets live in `public/images/*` and `public/icons/*` (Figma exports); icons render through `components/common/Icon.tsx` (`next/image` with `unoptimized` for SVGs).

## Auth pages (`/login`, `/signup`)

- Auth calls are wired through `handleSubmit()` in `AuthForm.tsx` (calls `authClient.signUp.email` / `authClient.signIn.email`); API errors render in a red `role="alert"` banner, success shows a message then `router.replace("/")` after 1.2s. `Navbar.tsx` (Sign In / Get Started) and `Cta.tsx` link to these two routes.
- Live-tested Nov 2026 against the dev server (HTTP harness): sign-up (seeker + recruiter) → session cookie → dashboard render → wrong-role redirect → sign-out → `307 /login`. better-auth rejects POSTs without an `Origin` header (`MISSING_OR_NULL_ORIGIN`) — browsers send it, scripts must too. The harness left `qa.*@example.com` test users in Atlas `hireloop_db.users`.
- One shared client component `features/auth/components/AuthForm.tsx` (`mode: "signin" | "signup"`), with pure validation in `features/auth/validation.ts` and types in `features/auth/types.ts`. `app/(public)/(auth)/login/page.tsx` and `app/(public)/(auth)/signup/page.tsx` are thin server wrappers that exist only to hold `metadata`. The nested `(public) > (auth)` route groups do not affect the URL — both routes stay `/login` and `/signup`.
- Inputs are uncontrolled — data is read in `onSubmit` via `Object.fromEntries(new FormData(e.currentTarget))`. Validation (required, email format, password ≥ 8, confirm-match on signup) runs in `validateAuthForm()` **before** any network call; `handleSubmit()` inside `AuthForm` is the single Better Auth integration point (sends `name`/`email`/`password`; on signin also `rememberMe` — read from the Remember me checkbox via FormData, default checked → absent key means `false` — while `confirmPassword` is always stripped).
- `lib/auth-client.ts` creates **two** clients: `authClient` (uses `baseURL: process.env.BETTER_AUTH_URL`) and a second bare `createAuthClient()` whose exported `{ signIn, signUp, useSession }` helpers ignore `BETTER_AUTH_URL` (same-origin default). Prefer `authClient.*` when wiring calls.
- The signup role radio group (`name="role"`, default `seeker`) is read via FormData like the other fields; `handleSubmit` passes it to `signUp.email`. `authClient` only typechecks `role` because `lib/auth-client.ts` registers `inferAdditionalFields<typeof auth>()` — keep the `import type { auth }` **type-only** (a value import would pull server code, e.g. mongodb, into the client bundle).
- No auth screens exist in `hireloop.fig`, so these pages reuse homepage tokens: card `#151516` / `rounded-[24px]`, inputs `#101010` / `border-white/20` / `rounded-[16px]`, primary `#5c53fe` / `rounded-[12px]`.

## Dashboards (`/dashboard/*`)

- **Guard chain (server-side, no `middleware.ts`)**: `app/(dashboard)/layout.tsx` calls `auth.api.getSession({ headers: await headers() })` → `redirect("/login")` with no session, then renders `DashboardShell`. Each `app/(dashboard)/dashboard/<role>/layout.tsx` calls `requireRole("<role>")` (`features/dashboard/guard.ts`) — wrong-role visitors get redirected to their own `roleHome`, so no role-specific URL ever renders for the wrong account. `session.user.role` goes through `normalizeRole()` (accounts predating the role field fall back to `seeker`).
- **Shell**: `components/layout/DashboardShell.tsx` (client) wraps everything in shadcn **`SidebarProvider` → `Sidebar` (left) → `SidebarInset`** — the built-in left Sheet below **`md` (768px, the component's own breakpoint)** and the `sidebar_state` cookie come for free; `--sidebar-width` is overridden to `15.5rem` (Figma 248px) through the provider's `style`. Don't pass `collapsible="none"`: it early-returns before the mobile branch, so the Sheet would never render — the default `offcanvas` is kept and `SidebarTrigger` renders only `md:hidden` (the Figma sidebar has no desktop collapse; Ctrl/Cmd+B is the component's hidden shortcut). Top bar: 56px with the Figma search input (`#0c0c0f`); `SidebarInset`'s stock `bg-background` is overridden to `#0e0e11`. `DashboardSidebar.tsx` sits on `SidebarHeader`/`SidebarContent`/`SidebarFooter` inside a `display: contents` wrapper (Inter must re-apply there — the Sheet content is portaled outside the provider's DOM): brand → identity card (avatar / name / email / role pill) → role nav through `SidebarMenuButton isActive` → "Explore" public links (spec-required; the Figma sidebar omits them) → Log out (`authClient.signOut()` + `router.push("/")`). Active state: longest match wins (exact for the dashboard home; prefix for the rest) so `…/jobs/new` highlights only its own item; clicking any link closes the mobile Sheet via `useSidebar().setOpenMobile(false)`.
- **Nav config**: `features/dashboard/data/nav.ts` — `roleNav` mirrors the three `HL 2.0/Sidebar` Figma variants (seeker: Dashboard/Jobs/Saved Jobs/Applications/Billing/Settings · recruiter: Dashboard/My Company/Add Job/Manage Jobs/Applications/Billing/Settings — "Add Job" comes from the newer `Add New Job` screen's sidebar · admin: Dashboard/Users/Companies/Jobs/Payments/Settings), plus `publicNav`, `roleHome`, `normalizeRole`.
- **Pages**: home pages (`dashboard/{seeker,recruiter,admin}/page.tsx`) built from Figma-decoded content in `features/dashboard/data/mock.ts`, using shadcn Card/Table/Badge + `features/dashboard/components/StatCard.tsx`. The recruiter "Add Job" screen (`dashboard/recruiter/jobs/new`) is built from `features/dashboard/components/JobPostForm.tsx` (Figma `Add New Job`, form 60% + live preview 40%) — demo only, no content API, submitting validates then shows a success banner. Sidebar active state is **longest-match**, so `…/jobs/new` lights only "Add Job", never both it and "Manage Jobs". All dashboard routes are dynamic (ƒ): better-auth hits the DB per request.
- **Tokens (Figma-decoded)**: sidebar `#08080a` — carried by the `--sidebar*` tokens that `globals.css` `:root` now sets to Figma values (dark-only app, no `.dark` class to flip the stock light ones; `@theme inline` maps them to `bg-sidebar`/`text-sidebar-*`), content `#0e0e11`, cards `#141418` / identity `#141416`, input `#0c0c0f`, active nav `#232327` (`--sidebar-accent`) + `#5c53fe` 2×16 indicator, logo `public/images/logo.png` (154×44) at `h-7`. Inter applies via `inter.className` on the shell root — the unlayered next/font class beats layered `font-heading`/`font-sans` utilities (the mobile Sheet is portaled outside that tree, hence the extra `inter.className` in `DashboardSidebar`). All other stock light `oklch` tokens stay untouched: dashboard primitives get explicit hex overrides instead.
